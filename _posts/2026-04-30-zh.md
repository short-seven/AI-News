### 1. OpenAI 揭秘「哥布林问题」：GPT 模型为何越来越爱提妖精？
**评分：9/10** · 来源：[OpenAI 官方博客](https://openai.com/index/where-the-goblins-came-from/) · 📰 Hacker News 热度：417 分

从 GPT-5.1 开始，OpenAI 的模型在回答中越来越频繁地使用"哥布林"（goblin）和"小妖精"（gremlin）等比喻。调查发现，问题根源在于为「书呆子人格」（Nerdy Personality）定制训练时，奖励信号无意中对含有「生物」隐喻的输出给予了更高评分。尽管 Nerdy 人格仅占 ChatGPT 回复的 2.5%，却贡献了 66.7% 的「哥布林」提及。更令人惊讶的是，这种风格通过训练迁移（style transfer）扩散到了非 Nerdy 场景。

**💡 关键洞察**：模型行为由无数微小的激励信号塑造，即使单个 reward 偏差微不足道，经过多轮 RL 训练也会被放大。这对 RLHF 的可控性敲响了警钟。

### 2. Claude Code 重大 Bug：commit 信息含「HERMES.md」会导致额外计费
**评分：9/10** · 来源：[GitHub Issue](https://github.com/anthropics/claude-code/issues/53262) · 📰 Hacker News 热度：1090 分

一位 Max 20x 计划用户发现，当 Git 仓库的 commit 信息中包含大写的 `HERMES.md` 字符串时，Claude Code 会将 API 请求路由到「额外用量计费」而非计划配额。这导致该用户被扣了 $200 额外费用，而其计划使用率仅 13%。该 bug 是大小写敏感的——`hermes.md`（小写）不会触发。

**⚠️ 影响**：任何在 commit 信息中引用过 HERMES.md 的用户，都会在不知情的情况下被额外计费。这是一个由系统提示注入（system prompt injection）机制引发的意外行为。

### 3. Copy Fail (CVE-2026-31431)：影响 2017 年以来所有 Linux 的内核提权漏洞
**评分：9/10** · 来源：[copy.fail](https://copy.fail/) · 📰 Hacker News 热度：856 分

一个存在近 10 年的 Linux 内核逻辑漏洞被曝光。该漏洞利用 `AF_ALG` 和 `splice()` 系统调用链中的 4 字节页缓存写入，仅需 732 字节 Python 脚本即可在所有主流 Linux 发行版上获取 root 权限。无需竞态窗口、内核偏移或特殊权限——只需一个普通用户账号。影响范围包括 Ubuntu、Amazon Linux、RHEL、SUSE 等所有自 2017 年以来的内核。

**🛡️ 缓解措施**：更新内核到包含修复提交 `a664bf3d603d` 的版本，或临时禁用 `algif_aead` 模块。对 Kubernetes、CI 运行器、多租户服务器尤为关键。

### 5. Vera：专为 LLM 设计的编程语言
**评分：8/10** · 来源：[GitHub - aallan/vera](https://github.com/aallan/vera) · 📰 Hacker News 热度：80 分

Vera 是一门全新编程语言，核心理念是「模型不需要是对的，只需要是可检验的」。主要设计创新：
- **没有变量名**：用结构化引用 `@Int.0`、`@Int.1` 替代，避免 LLM 最常见的命名错误
- **强制合约**：`requires` 前置条件 + `ensures` 后置条件，由编译器和 SMT 求解器静态验证
- **效果类型**：函数必须声明副作用（纯函数、HTTP、LLM 推理等）
- 编译目标为 WebAssembly，可在命令行或浏览器运行

### 9. Zig 项目严格禁止 AI 贡献的深层逻辑
**评分：8/10** · 来源：[Simon Willison](https://simonwillison.net/2026/Apr/30/zig-anti-ai/) · 📰 Hacker News 热度：161 分

Zig 软件基金会社区副总裁 Loris Cro 撰文解释了 Zig 全面禁止 LLM 辅助贡献的原因。核心观点是**「贡献者扑克」——赌注押在贡献者身上，而非代码本身**。Zig 核心团队审查 PR 的首要目的不是获取代码，而是培养可信赖的长期贡献者。LLM 辅助打破了这一投资回报链——即使 LLM 帮你提交了完美的 PR，Zig 团队花在审查上的时间也无法转化为新的可靠贡献者。

> 有趣的是，Bun（最知名的 Zig 项目，已被 Anthropic 收购）使用了 Zig 的 fork 版本并大量使用 AI 辅助，但明确表示不会将 AI 生成的代码上游到 Zig 主仓。
